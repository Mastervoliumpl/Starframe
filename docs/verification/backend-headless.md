Milestone 0.7.0 issue #66, in progress. The first increment is `e4e0762` on draft PR #78. Tauri and the internal `starframe_headless` binary call the same Rust operation functions for mod actions, collection sharing, package queue actions, game selection, runtime preparation and readiness. The desktop still owns its window, file pickers, subscriptions, update UI and background scheduling. The command takes an explicit absolute app-data directory and ends when its requested work completes. It is an internal test surface, not a stable public CLI.

The headless integration test uses a temporary Lua source and app-data directory. It checks import and local package preparation, the structured error for an unavailable approved release, collection creation and selection, restart persistence and refusal to open the same storage while another process owns it. The shared package tests cover verified download completion, cancellation and recovery; the CLI delegates to that queue without another rule set. The `tests/native/headless.mjs` check requires separately staged integration resources. It creates a fake Unity-layout game using an inert copy of Windows `ping.exe`; setup and launch use that copy only. It checks selection, empty readiness before setup, confirmed activation after setup and an unchanged fake executable. It does not launch or modify Sanctuary.
