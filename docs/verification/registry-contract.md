Milestone 0.7.0 issue #82 is in progress. The original release, trust and download fixtures pin website v1 contract revision `fcd81be6667e2595166698178d5f55074c5ee92a`; the read-only website main reference when work started was `ba8803aea4b6a067c1f9c60d5eb3ac33c7358567`. The installation boundary pins that exact new revision's `contracts/v1/installation.md`, `schema.json` and `install-fixtures.json`. `tests/fixtures/registry-installation-v1.json` retains the website's declaration/inventory examples and four synthetic full release envelopes signed with the website reference. The website schema and signature verifier accepted all four. Rust accepts release schema 2 only with a valid installation schema 1 declaration and verifies its signature with the existing key/security/identity gates. Missing plans, unknown fields or versions, unsafe paths and mismatched loader/destination shapes fail. An unsigned replacement plan fails verification. Schema 1 releases have no inferred declaration. This is contract acceptance; archive preparation and deployment remain in progress under #86.

The native boundary accepts only the production API and website hosts over HTTPS, or explicit `127.0.0.1` HTTP fixtures. Requests have a 30-second timeout, no redirects or automatic retries, a 4 MiB JSON cap, duplicate-key rejection and a cancellation receiver. Bearer credentials are supplied in memory to the Rust client; they are not held by Svelte. Errors preserve the website code, message, request ID, field problems and retry delay. The native types distinguish numeric ModID, UUID ReleaseID, lowercase SHA-256 and publication order. Version labels remain text. Schema 15 introduced exact registry references; schema 16 adds registry trust streams and hash decisions. A saved release cannot silently change hash. Old catalog IDs are not converted into the new table.

Local tests parse the pinned approved, unavailable, blocked, list and error examples; exercise a 2 GiB byte count, wrong IDs and unsafe integers; and use a loopback HTTP fixture for bearer placement, bounded query encoding, redirect refusal, cancellation and invalid JSON. A restart test confirms exact references and hash-conflict refusal. These are local contract and persistence checks. No deployed website endpoint, live credential, signed metadata or real archive was used. Registry login, trust verification, downloads and installation are assigned to #83–#86. The old desktop catalog remains until #88–#89 replace its consumers.

Website main advanced to `3f983dd08ebb30cccbb7be7cfb8030ae3549c31b` after these fixtures were pinned. Its schema adds a required `modType` to ordinary discovery and a separate type filter; the website calls that type an author declaration, not evidence of archive contents. It also retires dependency-amendment mutation routes. The signed release fields used by the current manager transport did not gain an installation declaration in this revision. #87 and #88 must use the then-current discovery and dependency contract after #86; `modType` cannot stand in for #101's signed code entry points or AI/map destination mappings. No manager implementation is claimed against the newer discovery shape yet.
