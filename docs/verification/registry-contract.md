The native boundary accepts only the production API and website hosts over HTTPS, or explicit `127.0.0.1` HTTP fixtures. Requests have a 30-second timeout, no redirects or automatic retries, a 4 MiB JSON cap, duplicate-key rejection and a cancellation receiver. Bearer credentials are supplied in memory to the Rust client; they are not held by Svelte. Errors preserve the website code, message, request ID, field problems and retry delay. The native types distinguish numeric ModID, UUID ReleaseID, lowercase SHA-256 and publication order. Version labels remain text. Schema 15 stores exact registry references in a separate table; a saved release cannot silently change hash. Old catalog IDs are not converted into the new table.

Local tests parse the pinned approved, unavailable, blocked, list and error examples; exercise a 2 GiB byte count, wrong IDs and unsafe integers; and use a loopback HTTP fixture for bearer placement, bounded query encoding, redirect refusal, cancellation and invalid JSON. A restart test confirms exact references and hash-conflict refusal. These are local contract and persistence checks. No deployed website endpoint, live credential, signed metadata or real archive was used. Registry login, trust verification, downloads and installation are assigned to #83–#86. The old desktop catalog remains until #88–#89 replace its consumers.
