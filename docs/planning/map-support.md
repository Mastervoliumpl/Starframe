# Map support evidence

Checked 2026-09-06. This is a source review for Starframe planning. No game, converter, or mod code was executed.

Maps can be treated as content folders. Remmy's converter writes `<folder>/<folder>.sanmap` as UTF-8 JSON, a preview, and a `Textures` directory containing the heightmap and texture assets. Its map references use `map/Textures/...`, so installation must preserve the folder and its relative paths. The current converter writes an empty `decals` list. [Converter source](https://github.com/Remmyboy/sanctuary-map-converter/blob/5017330832c6e78e51d6a6bad194b856f3c0cedd/app/SanctuaryMapConverter/Core/Converter.cs)

The play destination is `<install>/engine/Sanctuary_Data/Maps/<folder>/`. An optional editor copy goes under `<install>/map-editor/SanctuaryMapEditor_Data/Maps/`, with prop references changed from `.santp` to `.sanprop`. The deployer skips the editor destination when it is absent. The author instructs users to restart the game after deployment because map files are cached at startup. [Path definitions](https://github.com/Remmyboy/sanctuary-map-converter/blob/5017330832c6e78e51d6a6bad194b856f3c0cedd/app/SanctuaryMapConverter/Core/GamePaths.cs), [deployer](https://github.com/Remmyboy/sanctuary-map-converter/blob/5017330832c6e78e51d6a6bad194b856f3c0cedd/app/SanctuaryMapConverter/Core/Deployer.cs), [deployment notes](https://github.com/Remmyboy/sanctuary-map-converter/blob/5017330832c6e78e51d6a6bad194b856f3c0cedd/README.md#deploying)

`MapLocalFiles` is a separate BepInEx runtime plugin, version `0.1.0`. It patches `EM.Lua.FilesCache.TryGetFileContent` with Harmony to serve missing `map/` paths from the loaded map folder. This supports Lua reads of map-local blueprints such as `.sandecal`; it does not install maps or convert them. The repository lists no standalone release for this plugin. These sources do not establish that ordinary maps with map-local textures require it. [Plugin source](https://github.com/Remmyboy/sanctuary-mods/blob/709562f3de3afc227cdc1c3b247fc9d808f1b0b0/MapLocalFiles/MapLocalFiles.cs), [release and loader notes](https://github.com/Remmyboy/sanctuary-mods/blob/709562f3de3afc227cdc1c3b247fc9d808f1b0b0/README.md)

The converter README says maps carrying decal blueprints require the fallback on every machine, but also reports invisible decal rendering as unresolved. It still attributes the fallback to SanctuaryHud; the newer mod repository contains the dedicated `MapLocalFiles` plugin above. Treat decal support as unfinished. [Decal limitations](https://github.com/Remmyboy/sanctuary-map-converter/blob/5017330832c6e78e51d6a6bad194b856f3c0cedd/README.md#decals--parked-at-90)

The SanctuaryDB PR snapshot covers game `0.0.1.11`, Steam build `25019767`. Its map page records 150 installed `.sanmap` files, the same play destination, readable JSON metadata, and the shipped `ExtraneousMapGen` tool. It explicitly leaves the full schema and editor launch path unconfirmed. Compiled editor code does not prove a usable editor. These findings cannot establish compatibility with build `25114838` or a later installed build. [Versioned map documentation at PR head](https://github.com/Mastervoliumpl/sanctuary-unit-db/blob/eba2038272a1d416c266e3884c51ac205539001d/src/content/modding/docs/0.0.1.11-25019767/maps.mdx)

Planning consequence: keep map content installation separate from runtime DLL installation. Before claiming current-build support, verify that a copied map is listed and loads with its assets, then test any required plugin and multiplayer behavior on an identified game build. This review establishes the source-level packaging and dependency distinction only.
